# 经验、偏好和任务续接

从 0.2.0 开始，桥接可以按需使用手机，并在任务后积累本机经验。

## 日常使用

继续用原来的「让手机做事」快捷指令，不需要重新生成：

- 问「现在几点」：助手用电脑的真实时钟回答，不为此打开手机 App。
- 做攻略：按需读取手机 App 内容或公开网页，在模型端整理，最后保存到你指定的位置。
- 助手缺少关键条件时会用 Bark 推送问题。再次运行同一个快捷指令回答，它会接回原任务。
- 想做别的事情时说「新任务：……」。有多个任务在等待时，用「回复 任务编号 内容」指定；编号可用 `iphone-agent-kit status` 查看。
- 付款、刷脸、解锁等仍由你本人处理。说「已经确认」「已经解锁」后继续；助手需要先核对状态，不能重试已经提交的动作。

普通问答不必询问保存位置。攻略、文稿等成果，本次明确指定的位置优先，其次用个人档案里的默认；两者都没有才问。你说「以后都这样」才会记录为长期习惯，「这次这样」只作用于当前任务。关键缺项需要问，标题、排版等普通细节由助手决定。

自动续接按请求来源区分。换了网络、来源地址变化后，可能需要显式指定任务编号；不要把不同来源的回答默认为同一个人。

## 经验怎么积累，是否拖慢任务

1. 服务启动、快捷指令叫醒 runner 时，读取整份精简经验与个人档案。
2. 用户说完指令后，把完整的精简经验一起交给助手。**不做相关性筛选，不额外调用检索模型。** 未经过 `/wake` 的客户端也会在任务开始时刷新文件。
3. 用户回复、正常任务、备用助手和恢复任务使用同一套经验与偏好上下文。
4. 任务先推送结果、完成手机收尾，再在独立后台队列中复盘。后台工作不持有手机工具。

读取本地文件通常很快，但模型处理新增文字仍有开销，不保证零延迟。精简经验默认最多 **1500 个字符**；后台会尝试合并重复内容。超限更新会被拒绝，保留原文；手工改成超长文件时暂不注入，`experience` 命令会提示整理，不会从中间截断。

后台复盘会使用少量模型用量，默认沿用 `ack.chain` 的 dsh / Claude 轻量模型。可配置独立 `review_chain`。复盘不给 Claude 的内置工具或 MCP；dsh 使用专用 ack profile，并禁用手机、文件、命令等插件。当前不支持 Codex 作为后台复盘模型；Codex 执行任务照常参与共享经验。

```json
{
  "experience": {
    "enabled": true,
    "max_chars": 1500,
    "review_enabled": true,
    "review_timeout_secs": 45,
    "review_chain": []
  }
}
```

`review_enabled: false` 关闭模型复盘，仍保存必要的操作事实；`enabled: false` 不在桥接任务中附带经验，也不排队复盘。个人档案、任务续接仍可用。

经验不是成功证明：工具调用没有报错不代表目标完成。没有足够证据时记录为候选/待验证，不能编造「正确路径」。参考经验不能覆盖付款、删除等规则，也不能把网页或 App 内容当成授权。

## 文件和统一读写入口

本机目录：`~/.config/iphone-agent-kit/`（可由 `IPHONE_AGENT_KIT_HOME` 改）。

```text
profile.md                     用户明确的偏好
experience/summary.md           每个助手都能读到的整份精简指南
experience/reviews/<任务>.json   做错/多做/正确步骤及证据引用
experience/traces/<任务>.jsonl   必要工具动作、耗时、错误码
work/checkpoint-<任务>.json      本轮已做、待做、待回答问题
tasks.json                      会话编号、任务关系、状态和进度
```

共享写入有文件锁、原子替换和版本校验，防止两个助手互相覆盖；旧的精简经验另存 `experience/history/`，方便找回。经验文件只在本机生成，个人运行数据不能提交到 GitHub。新增操作记录不保存完整控件树、截图、输入消息、验证码或凭据；只保留动作结构、有限白名单导航控件及机器错误码。原有 `tasks.json` 仍包含个人任务文字，不要对外分享整个配置目录。

查看经验：

```bash
iphone-agent-kit experience
iphone-agent-kit experience --json
```

修改后用文档写回（建议带上上一步看到的版本）：

```bash
iphone-agent-kit experience --write /path/to/精简经验.md --revision 版本号
```

其他支持 stdio MCP 的助手也可以连接同一份本机经验，无需依赖厂商自己的记忆：

```json
{
  "mcpServers": {
    "iphone-agent-kit": {
      "command": "python3",
      "args": ["/安装目录/iphone-agent-kit/bridge/assistant_mcp.py"]
    }
  }
}
```

把安装目录替换为实际位置（通常为 `~/.local/share/iphone-agent-kit` 的绝对路径；MCP 参数里的 `~` 不一定展开）。桥接会自动为三个 CLI 接入，不修改用户的全局配置或 dsh profile 文件。独立连接默认只有本机辅助工具；不自动启用手机控制。

工具有：`kit_context_read`、`kit_experience_write`、`kit_profile_set`、`kit_checkpoint`、`kit_time`、`kit_fetch_url`。偏好写入必须引用桥接本轮用户原话；独立 MCP 没有这份用户原话，不开放偏好修改或桥接任务进度写入。经验可以跨助手读写。

公开网页工具不带登录态，只读公开 HTTP(S) 文字网页，限制响应大小和超时；禁止访问本机/私网，检查重定向和实际连接地址。若本机 DNS 为域名返回非公网地址（例如部分代理的 Fake-IP 模式），会拒绝访问，不自动改代理/DNS 或绕过检查。它不能代替搜索引擎或读取需要登录的 App 内容。统一搜索服务尚未接入，可使用助手已开放的联网能力或按需访问手机 App。

## 为什么关闭 runner 后还能续接

关闭手机 runner、退出 CLI 进程，都不等于删除模型会话。桥接保存原生会话编号：Codex 用 `exec resume`，Claude 用 `--resume`，dsh 用 `--session-id`。

询问对应 `waiting_user`，解锁对应 `waiting_unlock`，付款/本人确认对应 `needs_confirm`。用户回答后，建立关联的新一轮任务，继承原助手、模型和进度，原等待记录标为已回答。原生会话没有编号时直接带进度恢复；原生会话明确报「不存在」且本轮未操作手机时，可重新启动一次并附带进度。其他错误不自动当成会话失效。

切换备用助手仍有未知动作结果的风险。进度不代替实际状态核对，发送、下单、付款等不能根据猜测直接重试。

## 自动锁屏与问答

runner 唤醒仍与用户说话并行；普通问答不再等待 runner 就绪。手机锁住时，电脑端的问答、计算和整理继续；真正需要手机时才检查并请求解锁。

完全没有使用手机的任务不按 Home。桥接只清理自己本次启动或使用的手机会话；其他助手占用、人手动交还时不强抢。任务结束与唤醒线程有同步保护，避免回答太快、收尾后 runner 反而被迟到的唤醒重新启动。

## 验证方式

离线测试不使用真实手机、模型或 Bark：

```bash
python3 -m unittest discover -s tests -v
```

可选 CLI 验收会使用少量模型用量，但只挂一个假手机 MCP，无法连接真实手机：

```bash
python3 tools/check-assistant-clis.py --agents dsh codex --conversation
python3 tools/check-assistant-clis.py --agents claude
```

真机测试需要用户先停下手机操作，再重启桥接服务进行；不要在用户使用手机或有正在运行任务时重启。具体通过和未验证项目见版本验收记录。
